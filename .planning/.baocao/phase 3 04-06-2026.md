## 6. Phân tích giải pháp lưu ảnh Inline dạng Base64
- **Cơ chế**: Khi người dùng insert hình ảnh vào Quill editor, editor sẽ tự động mã hóa nhị phân ảnh đó thành chuỗi Base64 dài chứa trong thẻ `img` (ví dụ: `<img src="data:image/png;base64,...">`). Chuỗi HTML này được gửi trực tiếp lên backend và lưu nguyên trạng vào cột `posts.content` (`MEDIUMTEXT`).
- **Lý do đây chỉ là giải pháp tạm thời**:
  1. **Quá tải cấu hình máy chủ**: Việc truyền tải chuỗi Base64 dung lượng lớn trong payload request POST sẽ dễ dàng chạm ngưỡng giới hạn của cấu hình PHP/Apache như `post_max_size` (thường mặc định là 8MB hoặc 20MB) và gây ra lỗi `413 Request Entity Too Large` hoặc timeout.
  2. **Phình to Cơ sở dữ liệu**: Dữ liệu text Base64 chiếm tài nguyên lưu trữ lớn hơn 33% so với file ảnh gốc, làm dung lượng DB tăng cực nhanh và gây chậm các lệnh truy vấn `SELECT` hay `LIKE` trên cột này.
  3. **Không an toàn triệt để**: Dù đã có `DOMPurify` ở client và kiểu cột `MEDIUMTEXT` ở DB hỗ trợ dung lượng lên tới 16MB chống cắt cụt dữ liệu, việc lưu trực tiếp ảnh vào DB vẫn là bad practice. Giải pháp chuẩn là upload ảnh qua API lên đĩa cứng/S3 rồi trả về link URL tuyệt đối để insert vào nội dung.
